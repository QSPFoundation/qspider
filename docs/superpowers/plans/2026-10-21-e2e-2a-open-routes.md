# Batch 2a — Opening routes & archives E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cover every game-opening route and archive format in the E2E suite — file/dialog opens of a single-game zip, a `.qsp` binary, a Cyrillic-named game, an includer (inclib) zip, a multi-game zip (shelved, not started), a `.7z`, and web-only URL `?game=` import — plus the two ⚠ fixes those routes expose, with unit coverage where E2E can't reach.

**Architecture:** Most routes reuse the existing `OperatePlayer.openGameFile(path)` ability with new fixtures, in a new `scenarios/open-routes.scenario.ts`, on both targets. Derived fixtures (`.qsp`, `.7z`, single-game/includer/multi-game zips) are generated by a shared framework-free builder run from web `global-setup.ts` and desktop `wdio.conf.ts onPrepare`. Two new capabilities are added: a web-only `openGameUrl` ability method (desktop throws, scenario is `webOnly`), and — if drivable — a desktop drag-and-drop path, with a unit-test fallback.

**Tech Stack:** Serenity/JS screenplay; Playwright (web) + WebdriverIO/tauri-driver/AT-SPI (desktop); Vitest via NX `test` targets; `@qsp/converters` (`readQsps`/`writeQsp`); `7z-wasm` (create `.7z`); `fflate` (zip, already used).

**Spec:** `docs/superpowers/specs/2026-10-21-e2e-phase2-design.md` and its companion `docs/superpowers/specs/2026-10-21-e2e-engine-inventory.md` (batch 2a).

## Global Constraints

- Run all tasks through NX targets (`nx run <proj>:test`, `nx run player-e2e:e2e-web` / `:e2e-desktop`), never direct vitest/playwright/wdio. Web E2E needs `CHROME_BIN=/usr/bin/chromium`; desktop E2E needs `PATH="$HOME/.cargo/bin:$PATH"` and runs only via `pnpm e2e:desktop` / `run-desktop-e2e.mjs` (never `wdio run` or the a11y wrapper directly).
- Follow `apps/player-e2e/README.md`: area layout; `elements.ts`/`tasks.ts`/`checks.ts` split; locate ONLY by `[data-qsp*]` / `[role=]` / `[data-qa]`; checks go through `seeEventually`, never `Ensure`; `tasks.ts` may import only `common/checks.ts`; no fixed sleeps; no dynamic `import()` outside `support/scenario.ts`; `screenplay/**` files ≤150 lines; `await` every `attemptsTo`.
- Single-target scenarios use `scenario.webOnly` / `scenario.desktopOnly` with the same base title; never branch inside a scenario.
- Fixture descriptor modules (`fixtures/*.ts`) stay free of any test-framework import (loaded by both runners).
- Desktop E2E stays headless and isolated (private runtime/home dirs; never the real session). Do not weaken `restartAppWithEmptyData` or the private-session guards.
- `pnpm check` must stay green; every required check (`frame`, `rust`, `e2e-web`, `e2e-desktop`) must pass before the PR merges.
- This is batch 2a: one PR. The two ⚠ fixes here (`.7z` drop, failed `?game=` loader) are approved to land in-batch; flag each in the PR body.
- First action on the branch: restore the stashed design-doc edits — `git stash pop` (the `2c-doc-edits` stash) is for the 2c branch, NOT this one; leave it stashed.

## Review Focus

- A `?game=` URL that is reachable but not a valid game (not only an unreachable URL) must still clear the loader and surface an error — pinned in Task 3.
- A Cyrillic path must survive the GTK dialog's autocomplete unchanged through activation (the `dialog.py` equality guard fails the open otherwise) — pinned in Task 5 (desktop).
- The start-vs-shelf boundary at exactly one game: a single-game zip starts; a two-game zip only shelves — pinned in Tasks 4 and 4b.
- A `.7z` produced by `7z-wasm` must be detected by `is7zip` and extracted by the importer (round-trip), not just assumed — pinned in Task 1 and Task 4.
- Re-opening the multi-game pack when its games are already on the shelf (desktop launches with them) must not duplicate or error — pinned in Task 4b.
