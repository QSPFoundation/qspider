# E2E Batch 2d — Saves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cover every §I save touch point with real-engine, real-storage E2E scenarios on both targets: several slots + clear, named saves, quicksave/quickload, Ctrl+S/Ctrl+O, `NOSAVE`, cancelling the saves panel resumes the engine, and saves surviving an app restart. The restart needs a new restart helper that keeps the data dir.

**Architecture:** One new fixture game, `saves` (packed as `saves.zip`, opened with `OpenGameFile` on both targets), with one action per save path and a `COUNTER=n` text that shows what was restored. The `screenplay/saves/` area gets separate save/load/clear buttons per slot, the quicksave slot, and `SeeSlotFilled`. Hotkeys go in `game/tasks.ts`. A new `OperatePlayer` capability, `restartPlayer`, restarts the player and keeps its data. On web it reloads the page in the same browser context, where IndexedDB persists. On desktop, `fresh-app.ts` is refactored so the existing wipe-and-restart and the new keep-data restart share one end-session → wait-for-exit → new-session path. Only the wipe step differs.

**Tech Stack:** Serenity/JS screenplay; web = Playwright (`CHROME_BIN=/usr/bin/chromium`); desktop = WebdriverIO + tauri-driver (`pnpm e2e:desktop` only); fixtures as `.qsps` + TOML `game.cfg`, zipped by `fixtures/build-fixtures.ts`.

**Spec:** `docs/superpowers/specs/2026-10-21-e2e-phase2-design.md` (decision: across-restart persistence is in, using a keep-data restart that stays fully isolated) and `docs/superpowers/specs/2026-10-21-e2e-engine-inventory.md` §I + the "2d" scenario list (suspected defect 13 is relevant).

## Global Constraints

- Everything runs through NX / the pnpm scripts. Never run vitest/playwright/wdio directly. Desktop runs only via `pnpm e2e:desktop` or `node apps/player-e2e/targets/desktop/run-desktop-e2e.mjs --spec <file>` after `pnpm nx run player-e2e:build-desktop-e2e`, with `PATH="$HOME/.cargo/bin:$PATH"`. Never touch the real session; never kill processes by name.
- Locate only by `[data-qsp…]` / `[data-qa…]` / `[role=…]`; `By` only in `elements.ts`; checks only via `seeEventually`; tasks wait via `support/presence`; no `Ensure`/`isPresent` outside `support/`; no fixed sleeps; no dynamic `import()`; `screenplay/**` files ≤150 lines; `tasks.ts` imports checks only from `common/checks.ts`.
- New fixture is opened via `OpenGameFile`, **not** added to the launch `game.cfg`. Markers are unique ALL-CAPS strings, referenced only through `fixtures/saves-game.ts`.
- Every scenario runs on both targets unless the plan says otherwise. A scenario becomes `scenario.webOnly` / `.desktopOnly` only on reproduced evidence (≥2 runs), with the reason in a code comment and in the PR body (cf. 2c's WebKit `sendKeys`).
- Emptiness/absence checks need a settled anchor (README "Emptiness needs a settled anchor"): a filled slot seen earlier in the same panel load, or a positive outcome that only the blocked path would have changed.
- Before every restart, check a settled "save written" anchor (`SeeSlotFilled` in the saves panel). Killing the app mid-flush is not what we test.
- Per-scenario timeout stays 45s. If the restart scenario needs more on desktop, **stop and report the measured time**; do not raise the timeout silently.
- ⚠ A fix that changes player-visible behaviour (e.g. the probe in Task 6) is **asked of the maintainer first**; it is not applied silently. Non-visible defects are fixed in this PR.
- The batch ends green on `pnpm check:full`. Verify `CHECKFULL_EXIT=` and the desktop `Spec Files:` line from the log body. A desktop retry (`specFileRetries: 2`) is expected, not a regression.

## Review Focus

- **Save written, app killed before it reached disk:** the restart scenario must prove persistence, not luck. → Task 7 anchors on `SeeSlotFilled` before restarting.
- **Overwriting an occupied slot:** saving to slot 1 twice and then loading gives the newer state. → Task 3.
- **Saves are per game:** another game's saves panel doesn't show the fixture's slot. → Task 3 (anchored on a filled slot of the other game).
- **Quickload with no quicksave:** a no-op with no error alert; state unchanged. → Task 5.
- **Stale `requestedAction$` after cancel** (probe, unverified): `requestedAction$` is set by Ctrl+O / NOSAVE-Esc and reset only by a completed save/load. So after cancelling, the next saves panel may still hide Save. → Task 6 probe. If reproduced, report and ask before fixing (visible).

## Task 1: The `saves` fixture game

**Files:** Create `fixtures/saves/saves.qsps`, `fixtures/saves/game.cfg` (`id = "saves"`, `title = "Saves game"`), `fixtures/saves-game.ts`; modify `fixtures/archives.ts`, `fixtures/build-fixtures.ts`; test `fixtures/build-fixtures.spec.ts`.

**Interfaces — Produces** `SAVES_GAME` (frozen, no framework imports):

```ts
export const SAVES_GAME = {
  path: ARCHIVES.savesZip.path,          // artifacts/fixtures/saves.zip
  title: 'Saves game',
  text: {
    start: 'SAVES START',
    counter: (n: number) => `COUNTER=${n}`,
    afterSavePanel: 'AFTER SAVE PANEL',  // code after `savegame` ran
    afterLoadPanel: 'AFTER LOAD PANEL',  // code after `opengame` ran
  },
  action: {
    goToRoom: 'Go to room', increment: 'Increment',
    save: 'Save', load: 'Load',                          // savegame / opengame, no path
    saveThenMark: 'Save then mark', loadThenMark: 'Load then mark',
    saveNamed: 'Save named', loadNamed: 'Load named',    // savegame / opengame 'named.sav'
    enableNosave: 'Enable nosave',
  },
  namedSave: 'named.sav',
} as const;
```

QSP content: `# start` → `*pl 'SAVES START'`, `counter = 0`, act `Go to room` → `gt 'room'`. `# room` → `*clr & *pl 'COUNTER=<<counter>>'`, with one act per `action` entry. `Increment`: `counter += 1 & gt 'room'`. `Save then mark`: `savegame & *clr & *pl 'AFTER SAVE PANEL'`. `Load then mark`: `opengame & *clr & *pl 'AFTER LOAD PANEL'`. `Enable nosave`: `nosave = 1 & gt 'room'`. The rest are a bare `savegame` / `opengame` with or without `'named.sav'`.

## Task 6: Ctrl+S / Ctrl+O and `NOSAVE`

**Files:** modify `scenarios/save-hotkeys.scenario.ts`.

- `Ctrl+S opens the saves panel to save`: `PressSaveHotkey` → `SeeRequestedSaveCommand('save')` → `SaveToSlot(1)`; counter 2; `Load` → `LoadFromSlot(1)` → back to the saved counter.
- `Ctrl+O opens the saves panel to load`: slot 1 at counter 1 → counter 2 → `PressLoadHotkey` → `SeeRequestedSaveCommand('load')` → `LoadFromSlot(1)` → `COUNTER=1`.
- `NOSAVE blocks quicksave`: counter 1 → F5 (allowed) → anchor `SeeQuickSaveFilled` → `Enable nosave` → counter 2 → F5 (blocked) → counter 3 → F9 → `COUNTER=1`. Only the blocked F5 at counter 2 could have changed this.
- `NOSAVE blocks Ctrl+S`: `Enable nosave` → `PressSaveHotkey` → `Increment` → `COUNTER=n+1` → `SeeNoPauseScreen`. The action result is the anchor: a panel opened by Ctrl+S would have paused the game.
- `NOSAVE: Escape opens the pause screen for loading only`: slot 1 saved before nosave → `Enable nosave` → Escape → `SeeRequestedSaveCommand('load')` → `SavesButton` → `LoadFromSlot(1)` restores.
- **Probe, stale `requestedAction$`:** `PressLoadHotkey` → `CancelSavesPanel` → `OpenSavesPanel` → does `SeeRequestedSaveCommand` still read `load` (Save hidden)? Record it in the ledger. If reproduced, it is a defect whose fix (reset `requestedAction$` on pause-screen close in `onClosePauseScreen`, `libs/game-state/src/pause-screen.ts`) changes visible behaviour → **ask the maintainer before applying**. If approved: a scenario `cancelling a load request restores the normal saves panel` + the fix.
