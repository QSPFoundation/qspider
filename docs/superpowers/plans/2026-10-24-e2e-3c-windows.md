# E2E 3c — Windows desktop E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the whole desktop scenario suite, main plus standalone, on `windows-latest` with tauri-driver, msedgedriver and WebView2. It becomes a required check that runs on every PR.

**Architecture:**

- **Platform layer for the desktop target.** `targets/desktop/platform/` holds `linux.ts` (today's behaviour, moved, not changed) and `windows.ts`, behind one interface `DesktopPlatform`:
  - `startDriver(env)`: spawn tauri-driver, adding `--native-driver <msedgedriver>` on Windows;
  - `appProcesses(driverPid)`: the app and its webview helper processes under the driver;
  - `waitForExit(procs)`;
  - `appRunning()`;
  - `appDataDirs(runDir, identifiers)`: the dirs to empty between scenarios;
  - `driverEnv(runDir)`: the per-run env, `XDG_*` on Linux.

  `wdio.conf.ts`, `fresh-app.ts` and `cast.ts` call the interface and never branch on `process.platform` themselves.

- **Windows isolation.**
  - The CI runner is ephemeral. Each scenario ends the session, waits for the app's process tree to exit (PIDs from the parent-PID tree via `Get-CimInstance Win32_Process`, never by name), then empties the app's own dirs.
  - Those dirs are `%APPDATA%\<identifier>` and `%LOCALAPPDATA%\<identifier>`, which includes `EBWebView`. The identifiers are `org.qsp.qspider` and, for standalone, `org.qsp.e2e.standalone`.
  - The Windows platform refuses to run unless `CI` is set or `--host-session` is passed, the same rule as the smoke runner. A developer's real app data is never touched.
- **Native file dialog through UI Automation.** `targets/desktop/uia/dialog.ps1` (PowerShell plus `System.Windows.Automation`) runs behind the existing `pickFileInNativeDialog(path)`, with no scenario changes. `native-dialog.ts` picks the AT-SPI or UIA driver by platform. The UIA driver:
  - finds the dialog: a window of class `#32770` that belongs to the app's process tree;
  - sets the file-name edit's value with `ValuePattern` (AutomationId `1148`);
  - invokes the Open button (AutomationId `1`) with `InvokePattern`;
  - checks that the dialog closed.

  It sends no keystrokes and never reads UI text. Failures exit 1 with a message, and the existing wrapper reports them as `Native file dialog: …`. A 22 s kill applies, as on Linux.

- **msedgedriver.** It is resolved at job time and must match the runner's WebView2 runtime version, read from the registry key `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`, value `pv`. The matching `edgedriver_win64.zip` is downloaded and put on PATH. The version is never hard-coded.
- **CI.**
  - A reusable workflow `e2e-desktop-windows.yml` with inputs `spec` (default: all) and `shard`. It also takes `workflow_dispatch` with `spec`, to run one spec on a branch.
  - `checks.yml` runs the main suite as a matrix of shards (wdio `--shard i/N`) plus the standalone suite.
  - An aggregating job named **`e2e-desktop-windows`** (`if: always()`) fails unless every shard passed, so there is one required context.
- **Defects found on Windows.** A real player bug gets a red `test(e2e)` commit, then its fix. Ask the maintainer first if the fix is player-visible. Never skip or relax a scenario on Windows to get green.
  - A Chromium-vs-WebKit difference in a harness-level split may get a per-engine variant with a stated reason. Scenario text stays unchanged.

**Tech Stack:** WebdriverIO 9 (`--shard`), tauri-driver + msedgedriver, PowerShell 5.1 UI Automation (`UIAutomationClient`), GitHub Actions `windows-latest`, Node 24.

**Spec:** `docs/superpowers/specs/2026-10-24-e2e-phase3-design.md`, "PR 3: Windows desktop E2E". The maintainer decided on the full suite, every PR, required, and GitHub Actions only.

## Global Constraints

- Branch `feat/e2e-3c-windows` in the main checkout, no worktree.
- **Windows runs only in CI.** Iterating means pushing the feature branch, which is a draft PR from Task 3 on, and running `gh workflow run e2e-desktop-windows.yml --ref feat/e2e-3c-windows -f spec=<file>`. The maintainer approves pushing the branch early. Post a one-line status per CI round.
- **Linux behaviour must not change.** After every refactor, run the Linux desktop specs it touches locally: core-flow, saves, shelf and the standalone suite, through `run-desktop-e2e.mjs`.
- Never kill processes by name. Stopping our own child or process tree by PID is fine. Never touch the maintainer's real session.
- On Linux, nothing in the Windows path runs. On Windows, nothing touches a non-CI host unless `--host-session` is passed.
- No `check:full` locally; CI on the PR is the gate. Locally: format, lint, typecheck, unit tests and the touched Linux specs.
- README Rules apply to any scenario or screenplay change (≤150 lines per file, no sleeps, locate by data-qsp/data-qa/role).
- SDD ledger: `.superpowers/sdd/2026-10-24-e2e-3c-windows/`. Record every Windows CI round in it: run URL, spec, result, root cause.

## Review Focus

1. **Process-tree isolation on Windows.** WebView2 helper processes (`msedgewebview2.exe`) can outlive the app briefly and hold files in `EBWebView`. The wipe must wait for the whole tree, and a failed delete must fail loudly, never be skipped. (Task 1 unit test on the tree walk; Task 3 CI round.)
2. **A dialog driver acting on the wrong window.** The dialog must belong to the app's process tree, so a stray `#32770` from another process is ignored. The value set must be read back before invoking Open. (Task 2)
3. **Driver and runtime version drift.** If the msedgedriver download fails or the version doesn't match, the job fails with a clear message, never a hang. (Task 3)
4. **Shard aggregation.** The aggregate job must fail if any shard failed, was cancelled or was skipped unexpectedly. Discriminate with a deliberate failure in one shard on a test run. (Task 5)
5. **Windows paths in fixtures and scenarios.** A test that builds a URL or compares a path with `/` may pass on Linux and fail on Windows for harness reasons. Fix the harness, never the product, unless the product is wrong. (Task 4)

  - `appDataDirs` lists the Roaming and Local dirs for both identifiers under the given env;

### Task 3: Windows CI workflow, first green on core-flow

**Files:**

- Create: `.github/workflows/e2e-desktop-windows.yml`
  - `on: workflow_call` with inputs `spec` (string, default `''` = all), `shard` (string, default `''`), `suite` (`main` | `standalone`), plus `workflow_dispatch` with the same inputs;
  - one job on `windows-latest`: checkout, pnpm 10.17.0, Node 24 + pnpm cache, frozen install, rust stable, rust-cache (`src-tauri`), `cargo install tauri-driver --locked`;
