# E2E Batch 2f — Themes and layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cover inventory §F (themes) and the layout part of §E with real-engine E2E scenarios:

- Aero mode;
- game-provided themes via `defaultTheme`, including their css/script links;
- the missing-`defaultTheme` fallback (approved ⚠ fix);
- runtime `change_theme`;
- the classic `qspgui.cfg` layout;
- a layer-reset check that discriminates (carried from 2e, ruling R7);
- the `forEachTheme` dimension on the theme-sensitive core flows.

The look variables (2f′) are a separate PR.

**Architecture:**

- The active theme becomes observable through a new `data-qsp-theme` marker on `qsp-game-root`. This is a small non-visible renderer change, per README "add a marker".
- Theme variants are fixtures: a game plus a `game.cfg` (`mode = "aero"`, or `themes` + `defaultTheme`), zipped and opened via `OpenGameFile` (conventions design, Themes).
- `forEachTheme(themes, title, body)` lives in `screenplay/support/` and expands to one tagged scenario per theme.

**Maintainer decisions (2026-10-22):**

- 2f and 2f′ are two PRs.
- Theme matrix: the core flows run under **aero + custom on web only**. Desktop instead runs each theme-feature scenario once. The real desktop risk is loading game-provided theme files through the Tauri protocol and Aero rendering under WebKit at all.
- If a desktop theme-feature scenario finds a theme-specific desktop bug, that is the signal to widen the desktop matrix.

**Tech Stack:** Serenity/JS screenplay; web = Playwright; desktop = WebdriverIO + tauri-driver; fixtures as `.qsps` + TOML `game.cfg` (+ theme `.html`), zipped by `fixtures/build-fixtures.ts`.

**Spec:**

- `docs/superpowers/specs/2026-10-21-e2e-phase2-design.md`: 2f, plus the approved fix "missing-`defaultTheme` Aero fallback".
- `docs/superpowers/specs/2026-10-21-e2e-engine-inventory.md` §E/§F and the 2f list.
- `docs/superpowers/specs/2026-10-20-e2e-conventions-design.md` "Themes".

## Global Constraints

- Same as 2e:
  - NX/pnpm only;
  - desktop only via `run-desktop-e2e.mjs`, one run at a time, wait for it;
  - never touch the real session or kill processes by name;
  - README Rules: locators, `seeEventually`, presence helpers, ≤150 lines per screenplay file, no sleeps (the page-clock exception stays scoped to counter-pause checks), ExecuteScript only in `support/page-script.ts`;
  - plain branch, no worktree.
- New fixtures are opened via `OpenGameFile`, not the launch `game.cfg`. At most 8 actions per location. Markers are unique ALL-CAPS strings, referenced only through `fixtures/*-game.ts`.
- Theme-rendered UI outside the `qsp-*` vocabulary gets elements under `screenplay/themes/<theme>/`, per the conventions design. Game- and theme-authored `data-qa` passes through and may self-mark fixture elements.
- `forEachTheme` variants of core flows are `webOnly` (maintainer decision). The theme-feature scenarios run on both targets.
- ⚠ Player-visible fixes: only the approved missing-`defaultTheme` fallback. Anything else visible: stop and report. Non-visible defects are fixed with RED→GREEN.
- Local verification: targeted specs per task; `nx format:check --all`, lint and typecheck before each commit; **one** `pnpm check:full` at the end, after the final review's fixes.
- CI follow-up from #172: this is the first PR without Rust changes. Confirm on the PR that `rust` shows **skipped** and the "main" ruleset still allows the merge. If not, report before changing CI.

## Review Focus

- **The theme leaks from the previous game** (probe, unverified): with a missing `defaultTheme`, `runGame` sets no theme (`current-game.ts:145-159`), so the previous game's theme may stay. → Task 4.
- **A game-provided theme whose css/script/font files load from the game folder.** On desktop this goes through the Tauri protocol path. A wrong path or case shows only there. → Task 3, both targets.
- **`change_theme` to an unknown name shows an error and keeps the current theme.** → Task 5.
- **Aero layout under WebKit** may place elements so that `isVisible()` reads false on desktop only. → Task 2, both targets.
- **Restart with a theme-layout layer:** `reloadLayers` must reset a layer that stays mounted. → Task 6.

**Interfaces — Produces:**

- `SeeActiveTheme(alias: string)`: `seeEventually` on `qsp-game-root`'s `data-qsp-theme` (`[data-qsp-theme]`). Built-in aliases: `qspider:classic`, `qspider:aero`.
- `forEachTheme(variants: ThemeVariant[], title: string, body: (player, variant: ThemeVariant) => Promise<void>, opts?: { webOnly?: boolean })`. It registers one scenario per variant, titled `${title} [${variant.name}]`, through `scenario` / `scenario.webOnly`. `ThemeVariant = { name: string; alias: string; e2eGamePath: string }`. Export `CORE_THEME_VARIANTS` (aero, custom).
- `e2e-theme.html`: `<qspider-theme name="e2e-custom">`, derived from `public/themes/classic.html` so every `qsp-*` marker the suite uses still renders. It adds:
  - a `<qsp-css-link>` (or the theme's link mechanism; check themes.ts) to `e2e-theme.css`;
  - a script link to `e2e-theme.js`, which appends `<div data-qa="e2e-theme-script">THEME SCRIPT RAN</div>` to the body;
  - an element `<div data-qa="e2e-theme-chrome">E2E THEME</div>` in the layout;
  - a **layout-level** `<qsp-layer name="themelay">` outside main content, holding `THEME LAYER`, for Task 6.

  If the css link's effect can only be observed via computed style, that check belongs to 2f′. Here, assert that the theme's own link element is present (marker via theme-authored `data-qa`), or skip the css assertion and record why.

- Game fixtures, one location set each:
  - `aero-game`: `AERO START`; actions `Next` → `AERO NEXT`; a `Show message` msg.
  - `themed-game`: `THEMED START`; actions `Show layer` / `Hide layer` (via the qspider module) for `themelay`; `Restart` (`gs 'qspider_restart'`).
  - `missing-theme`: two zips. `missing-aero.zip` has `mode = "aero"` and `defaultTheme = "no-such-theme"`. `missing-classic.zip` has no mode and `defaultTheme = "no-such-theme"`. Start `MISSING START`.
  - `gui-cfg-game`: a classic game with a `qspgui.cfg` moving e.g. the stats panel into a different dock. Write the cfg using the format `qsp-gui-cfg.ts` parses; read `parseCfg`.
  - A small `change_theme` location may live in `aero-game` or `themed-game`: actions `To aero` → `gs 'qspider_change_theme', 'qspider:aero'`, `To missing` → `gs 'qspider_change_theme', 'no-such'`.
